# Web 知识搜索验收说明

## 1. 页面入口

```text
GET /search
```

首次打开只显示搜索表单，不执行查询。

## 2. 支持参数

| 参数 | 含义 | 边界 |
|---|---|---|
| `q` | 搜索内容 | 必填，去除首尾空白后 1–500 字符 |
| `limit` | 结果数量 | 1–50，默认 10 |
| `path_prefix` | 相对路径前缀 | 可选 |
| `tag` | 标签 | 可重复，可选 |

所有参数在调用 Application Service 前完成 Web 层边界检查。领域层仍保留自身查询校验。

## 3. 结果内容

每条结果展示：

- 标题；
- 标题层级；
- 笔记正文片段；
- 相对路径；
- 起止行号；
- 匹配方式；
- 相关度。

这使用户可以回到原始 Obsidian 文件核查上下文。

## 4. 安全边界

- 页面使用 Jinja 默认自动转义；
- 笔记标题与正文不使用 `safe` 过滤器；
- 测试使用 `<script>` 标记验证其被输出为转义文本；
- 空查询、超长查询和非法 limit 不调用业务端口；
- 搜索路由只调用 `WebApplicationPort.search()`；
- 关键词搜索不要求模型、Embedding Provider 或 API key。

## 5. 验收场景

### 场景 A：首次访问

预期：200；显示搜索内容、路径、标签和结果数输入；不执行搜索。

### 场景 B：非法输入

预期：400；显示可理解的字段错误；port 调用次数保持 0。

### 场景 C：带过滤查询

请求：

```text
/search?q=agent&limit=7&path_prefix=Research&tag=ai&tag=course
```

预期：查询、limit、路径和两个标签原样传入业务端口。

### 场景 D：带来源结果

预期：显示 `Research/Agent.md · 第 12–18 行`、匹配方式和正文；正文 HTML 被转义。

### 场景 E：无匹配

预期：200；显示“没有找到匹配结果”，不把空结果当成系统错误。

### 场景 F：真实本地链路

使用临时 Vault 写入 `Architecture.md`，通过真实 Application Service 同步，再从 Web 请求搜索 `durable recovery`。

预期：200；页面包含文件名和匹配正文；全程无 Provider 配置。

## 6. 当前限制

- T7 仅提供关键词搜索页面；混合检索的 Provider 选择尚未开放到 WebUI。
- 页面不直接打开用户本地 Obsidian URI，以避免公开部署产生不正确或危险链接。
- 单个标签输入框用于普通交互；URL 层支持重复 `tag` 参数。
- 搜索同步操作仍由 CLI 或未来受控管理入口执行。
